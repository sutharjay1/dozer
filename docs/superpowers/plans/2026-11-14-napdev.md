# napdev Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A CLI, `napdev next dev`, that holds a Next.js app's dev port and runs the real `next dev` only while pages are being requested.

**Architecture:** One small gate process per app listens on the public port, proxies HTTP to a hidden-port `next dev` child it starts on demand, and terminates the browser's dev websocket itself so a sleeping server is invisible to open tabs. A machine-wide coordinator daemon, reached over a unix socket, sees every gate and tells the least recently used one to sleep when the limit is exceeded. All timing and limit rules live in two pure units (`Gate`, `chooseVictims`) so they are tested without processes.

**Tech Stack:** Node 20+, TypeScript, `ws` (only runtime dependency), vitest, tsup (single-file CLI bundle), Playwright (spikes and the acceptance test only), pnpm.

**Spec:** `docs/superpowers/specs/2026-11-14-napdev-design.md`

## Global Constraints

- macOS and Linux only. Node 20+. Published to npm as `napdev`.
- Runtime dependencies: `ws` and nothing else.
- Supported: Next.js 15 and 16, webpack and Turbopack, App and Pages router. Next 14 is best effort and never a reason to stop.
- Defaults, verbatim from the spec: `idle` 10 min, wake timeout 120 s, `maxAwake` 2, grace 60 s, websocket ceiling 60 min after the last HTTP request, 3 failed wakes in a row.
- A sleeping gate process stays under 60 MB RSS.
- `Host` is forwarded unchanged. The child sees `NAPDEV_PUBLIC_PORT`.
- `NAPDEV=0` runs the real `next dev` untouched.
- napdev's own start-up failure falls back to plain `next dev`; there is no live hand-back later.
- No orphan processes: every stop is verified.
- Project root is a new git repo `napdev/`. All paths below are relative to it.

## Review Focus

Failure modes the spec implies but does not spell out. Each has a test in Task 6.

1. A POST with a large body arrives while the app is waking: the body reaches Next intact.
2. The client disconnects while its request is held during wake: in-flight count returns to 0 and nothing throws.
3. A streaming response (RSC stream, SSE) stays open past `idle`: it counts as in flight, is not buffered, and is not cut.
4. The gate reuses a kept-alive upstream connection from before a sleep: the first request after wake must not fail with a reset.
5. The browser resolves `localhost` to `::1` while the child listens on `127.0.0.1`: the public port answers on both families.

`spawnChild` runs `node <nextBin> dev <passthrough> --port <hiddenPort> --hostname 127.0.0.1` with `detached: true`, so the child leads its own process group, and sets `NAPDEV_PUBLIC_PORT`. `stopTree` signals the group (`-pid`) with SIGTERM, waits `termGraceMs`, sends SIGKILL, then lists processes by group id and throws `TreeSurvivedError` if any remain. `waitReady` resolves on the first HTTP response of any status from `127.0.0.1:<hiddenPort>`.

```ts
export type GateState = 'asleep' | 'waking' | 'awake'
export type SleepReason = 'idle' | 'evicted' | 'manual' | 'exit' | 'crashed'
export class WakeTimeoutError extends Error {}
export class WakeFailedError extends Error {}
export interface GateSnapshot { state: GateState; inFlight: number; lastHttpAt: number | null;
  childPid: number | null; hiddenPort: number | null; failedWakes: number }
export interface GateDeps {
  config: AppConfig
  startChild(signal: AbortSignal): Promise<ChildHandle>     // spawn + waitReady; rejects if the child exits first
  stopChild(child: ChildHandle): Promise<void>
  onChange(snapshot: GateSnapshot, reason?: SleepReason): void
  now?(): number                                              // default Date.now
}
export class Gate {
  constructor(deps: GateDeps)
  ensureAwake(): Promise<number>        // resolves the hidden port
  noteHttpStart(): void
  noteHttpEnd(): void
  noteServerFrame(): void               // a frame went from Next to a connected browser
  sleep(reason: SleepReason): Promise<void>
  resetFailures(): void                 // clears failedWakes and the cooldown
  snapshot(): GateSnapshot
}
```

Rules the tests pin:
- Idle sleep fires when `inFlight === 0` and `now − lastActivity ≥ idleMs`. `lastActivity` is the later of the last HTTP start/end and the last server frame, where a server frame counts only if it arrived within `wsCeilingMs` of the last HTTP request.
- A wake that exceeds `wakeTimeoutMs` stops the child and rejects with `WakeTimeoutError`. A wake whose child exits rejects with `WakeFailedError`. Both increment `failedWakes`; a successful wake resets it to 0.
- When `failedWakes ≥ maxFailedWakes`, `ensureAwake` rejects with `WakeFailedError` without starting a child until `failedCooldownMs` has passed since the last failure. `resetFailures()` lifts the cooldown at once; a manual wake calls it first (Task 8).
- A child exit while awake moves to `asleep` with reason `crashed`.

```ts
// sockets.ts
export class SocketHub {
  constructor(gate: Gate)
  handleUpgrade(req: http.IncomingMessage, socket: Duplex, head: Buffer): void
  onWake(hiddenPort: number): void     // send RELOAD_FRAME to every held browser socket, then close it with code 1012
  onSleep(): void                      // drop upstream sides; browser sockets stay open and silent
  browserCount(): number
}
// proxy.ts
export function createGateServer(o: { gate: Gate; sockets: SocketHub; tail: LogTail }): http.Server
export function listenPublic(server: http.Server, port: number, hostname: string | null): Promise<void>
```

Decisions:
- `export const RELOAD_FRAME = '{"action":"reloadPage","type":"reloadPage"}'` in `sockets.ts`, exactly this string (spike 1: Next 15 reads `action`, Next 16 reads `type`).
- The gate's `onChange` drives the hub: a change to `awake` calls `sockets.onWake(hiddenPort)`, a change to `asleep` calls `sockets.onSleep()`. The test helper and Task 7's `dev.ts` both wire it this way.
- Every upgrade is accepted by the hub. If the gate is awake the hub opens an upstream websocket to `ws://127.0.0.1:<hiddenPort><same path>` with the original `Host`, `Origin`, `Cookie` and subprotocol, and bridges both ways. Upstream-to-browser frames call `gate.noteServerFrame()`; browser-to-upstream frames do not. Upgrades never call `ensureAwake`.
- HTTP: `noteHttpStart`, `await ensureAwake()`, pipe request to `127.0.0.1:<hiddenPort>` with all headers unchanged, pipe the response back unbuffered, `noteHttpEnd` when the response closes or the client aborts.
- No upstream connection pooling: each proxied request opens its own connection (`agent: false`).
- `WakeTimeoutError` → `504` plain text. `WakeFailedError` → `502` plain text containing the log tail and the line `Run with NAPDEV=0 to bypass napdev.`
- `listenPublic` with `hostname === null` listens on `::` with dual-stack so both `127.0.0.1` and `::1` answer.

```ts
// protocol.ts
export const PROTOCOL_VERSION = 1
export function socketPath(home: string): string               // <home>/coordinator.sock
export interface AppView { id: string; name: string; cwd: string; publicPort: number; pid: number; pinned: boolean
  state: GateState; inFlight: number; lastHttpAt: number | null; rssBytes: number }
export type GateMsg = { t: 'hello'; v: number; app: Omit<AppView, 'state' | 'inFlight' | 'lastHttpAt' | 'rssBytes'> }
  | { t: 'report'; state: GateState; inFlight: number; lastHttpAt: number | null; rssBytes: number }
export type CoordMsg = { t: 'sleep'; reason: 'evicted' | 'manual' } | { t: 'wake' } | { t: 'reject'; reason: 'version' }
export type CliMsg = { t: 'list' } | { t: 'sleep'; target: string } | { t: 'wake'; target: string }   // target: id, or '*'
export type CliReply = { t: 'apps'; apps: AppView[] } | { t: 'ok'; count: number }
// policy.ts
export interface Limits { maxAwake: number; memoryBudgetBytes: number | null; graceMs: number }
export function chooseVictims(apps: AppView[], limits: Limits, now: number): string[]   // ids, in the order to sleep
// client.ts
export interface CoordinatorClient { connected: boolean; report(m: Extract<GateMsg, { t: 'report' }>): void
  onCommand(cb: (m: CoordMsg) => void): void; close(): void }
export function connectGate(hello: Extract<GateMsg, { t: 'hello' }>, home: string): Promise<CoordinatorClient>   // never rejects
export function askCoordinator(msg: CliMsg, home: string): Promise<CliReply | null>    // null when no coordinator runs
```

Decisions:
- Wire format: newline-delimited JSON over the unix socket.
- `chooseVictims`: over-limit means more than `maxAwake` apps in `awake` or `waking`, or their `rssBytes` sum above the budget. While over the limit, pick the app with the oldest `lastHttpAt` among those that are `awake`, not pinned, `inFlight === 0`, and `lastHttpAt === null || now − lastHttpAt ≥ graceMs`. If none qualifies, stop: the limit is soft.
- The server re-runs the policy on every report and every 5 s, and sends `sleep/evicted` to each victim.
- `connectGate`: connect; on failure remove a stale socket file, spawn `napdev __coordinator` detached with stdio ignored, retry for 2 s; if still failing or on `reject`, return `connected: false`. A gate with `connected: false` runs with the idle rule only.
- The daemon exits 10 s after its last gate disconnects, and immediately if the socket path is already served.
- `dev.ts` reports on every `Gate` change and every 10 s (with `treeRssBytes`), sends `pinned` in `hello`, maps `sleep` to `gate.sleep(reason)` and `wake` to `gate.resetFailures()` followed by `gate.ensureAwake()`.
